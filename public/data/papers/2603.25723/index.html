Natural-Language Agent Harnesses

Authors: Linyue Pan, Lexiao Zou, Shuo Guo, Jingchen Ni, Hai-Tao Zheng

Source: https://arxiv.org/abs/arXiv:2603.25723

Generated summary artifact for 2603.25723

Thesis

The design-pattern layer inside agent harnesses can be made explicit as an executable natural-language object under shared runtime assumptions.

Core Problem

Agent harness design logic is usually buried in controller code and runtime-specific conventions, making it difficult to transfer, compare, and study as a scientific object.

Key Novelty

Externalizing agent harness logic as explicit, executable natural-language objects (NLAHs) interpreted by a shared Intelligent Harness Runtime (IHR), enabling better study, comparison, and modularity of agent control.

Key Contributions

  • Demonstrated operational viability of Natural-Language Agent Harnesses (NLAHs) executed by an Intelligent Harness Runtime (IHR) across coding (SWE-bench Verified) and computer-use (OSWorld) benchmarks.
  • Showed that the shared runtime and harness logic significantly influence agent behavior and process metrics (e.g., prompt tokens, LLM calls, runtime), even if overall performance changes are subtle.
  • Provided evidence that harness modules can be composed and ablated, with varying effects on performance and problem-solving strategies, suggesting modules help by tightening solution paths.
  • Successfully migrated code-based harnesses to NLAH representations, leading to performance improvements and a shift towards more robust, artifact-backed verification and durable state, especially in OSWorld.

Results

  • Shared runtime charter and benchmark-specific harness logic materially change agent behavior and process metrics (e.g., tokens, calls, runtime) more than overall performance, indicating real behavioral control.
  • Harness modules can be composed and ablated, with their effects concentrating on boundary cases that flip under changed control logic, rather than uniformly shifting benchmark scores.
  • Explicit structure provided by modules (e.g., File-backed State, Self-Evolution) helps by tightening the path from intermediate behavior to evaluator acceptance, rather than simply expanding the search space.
  • Migration from native code harnesses to reconstructed natural-language harnesses is viable, can improve performance and shifts behavior towards more robust, artifact-backed verification and durable state management.

Limitations

  • Natural language is inherently less precise than code, making it difficult to faithfully recover some harness mechanisms, especially those relying on hidden service-side state, proprietary schedulers, or training-induced behaviors not observable from released artifacts.
  • Runtime contamination remains a risk, where a strong shared runtime charter might absorb part of the behavior one might otherwise attribute to harness text.
  • Module-level ablation studies, while informative, do not strictly establish causal identification; textual representations can introduce confounds like instruction salience and prompt length.
  • Externalizing harness modules may lower the barrier to spreading risky workflows, as harnesses mediate tool use and artifact handling, potentially introducing new attack surfaces for prompt injection, malicious tool grafting, or supply-chain contamination.
