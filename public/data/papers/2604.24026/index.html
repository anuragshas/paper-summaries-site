From Skill Text to Skill Structure: The Scheduling-Structural-Logical Representation for Agent Skills

Authors: Qiliang Liang, Hansi Wang, Zhong Liang, and Yang Liu

Source: https://arxiv.org/abs/arXiv:2604.24026

Generated summary artifact for 2604.24026

Thesis

LLM agents currently rely on text-heavy skill representations (e.g., SKILL.md files), which entangle invocation interfaces, execution structure, and resource use, making skill management and execution difficult for machines. Introducing a structured, three-layer Scheduling-Structural-Logical (SSL) representation, derived from cognitive linguistic theories and instantiated with an LLM-based normalizer, significantly outperforms text-only baselines in Skill Discovery and Risk Assessment, enabling more inspectable, reusable, and operationally actionable skill representations.

Core Problem

Current agent systems represent skills as text-heavy artifacts (e.g., SKILL.md files) where machine-usable evidence is largely embedded in natural-language descriptions, leading to a representational bottleneck where semantically distinct properties are collapsed into a single textual surface.

Key Novelty

The first structured representation (Scheduling-Structural-Logical, SSL) designed specifically for disentangling agent skill artifacts into three layers.

Key Contributions

  • In Skill Discovery, MRR@50 improved by +0.080 (from 0.649 to 0.729) over the strongest text-only baseline (Desc + Source Outline).
  • In Risk Assessment, macro F1 improved by +0.100 (from 0.409 to 0.509) over the complete source document baseline (Full SKILL.md).
  • SSL provides useful evidence across distinct skill-centered tasks (interface-level for discovery, action/resource-level for risk) while complementing the original source document.

Results

  • SSL-derived representations significantly outperform text-only baselines in both Skill Discovery and Risk Assessment.
  • The best performance in Skill Discovery is achieved by combining description with rich SSL-derived fields (Desc + SSL-Rich).
  • For Risk Assessment, combining the complete source document with SSL (MD + SSL) yields the best macro F1, improving over using the full document alone.
  • SSL makes task-relevant evidence explicit, aiding downstream systems in selecting and assessing skills without losing access to the original source artifact's context.
  • SSL is not a replacement for the source document but acts as an effective evidence interface.

Limitations

  • Static runtime actions: SSL is extracted from static artifacts and cannot determine dynamic actions (e.g., downloaded payloads, constructed commands, conditional resource access).
  • Normalizer fidelity: LLM-based normalization may omit relevant facts, over-regularize the source, map ambiguous behavior to coarse enums, or infer hidden intent.
  • Evaluation scope: Experiments cover Skill Discovery and Risk Assessment, not actual agent use during planning, execution, monitoring, or post-hoc refinement.
  • Skill Discovery benchmark: Uses automatically generated candidates filtered by a realism annotation protocol, not fully human-authored requests.
  • Model-mediated Risk Assessment: Current risk labels cover 252 skills and come from a multi-model binary voting pipeline with second-pass review for disagreed dimensions. Results should be interpreted as static risk-identification performance, not a substitute for expert security audit or runtime safety evaluation.
